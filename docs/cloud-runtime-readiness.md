## Implementation

- Separate official Cloud channels, threads, messages, drafts, private durable jobs and delivery attempts. Real traffic is never mislabeled as the legacy simulated test inbox. Owner controls support review/automatic modes, manual reply drafts, approval, takeover/release and bounded retries after definite rejection. Automatic mode additionally requires automation entitlement.
- Standard Meta Embedded Signup: one-use, actor/workspace-bound, ten-minute state; server-side code exchange; app/scopes/token expiry/data-access expiry/WABA target and phone ownership checks; encrypted credential saved before registration/subscription; failure never activates a channel. PIN is transient. Browser completion requires both the SDK code and trusted Facebook completion origin. Coexistence-specific onboarding is not claimed.
- `/api/webhooks/meta`: verification challenge and raw-body HMAC before parsing. Every mapped event is persisted/deduplicated before success; all batch items are attempted even when one fails. Unmapped phone/WABA pairs are deliberately ignored without storing unrelated business data. A mapping conflict or full mapped queue returns 503 for retry. Meta metadata supplies phone/WABA; callers cannot select a tenant.
- Private queue bounded at 1,000 unresolved jobs/workspace. Subscription expiry/quota blocks new active-thread projection and paid processing, not mapped durable acceptance. Existing thread history survives. Projection and reservations roll back independently of acceptance. Per-customer ordering and bounded per-workspace candidate selection prevent an over-limit customer monopolizing the worker. A backlog can still delay its own customer; monitoring is mandatory.
- Worker: one job per authenticated POST, three-minute lease, five processing attempts, current revision/owner takeover checks. AI uses business products/FAQs/information with existing grounded retrieval/prompt and Iraqi Arabic policy; no business fact generation outside supplied knowledge. Shared AI monthly quotas, owner daily 50 cap and WhatsApp minute/day generation limits remain. AI/STT provider-start ambiguity consumes the reservation and requires human review instead of repeating paid calls.
- Dispatch checks live entitlement, immutable draft/source revision, human approval and 24-hour customer window. No templates or business-initiated outreach. Provider acceptance is distinct from sent/delivered/read. Statuses progress monotonically. Timeout/5xx/ambiguous result pauses for reconciliation, never blind retry. Definite rejection allows at most three attempts; owner can explicitly retry an unchanged rejected reply. Takeover prevents dispatch before the SQL permit; it cannot recall an already permitted/in-flight HTTP request.
- AES-256-GCM tokens bind workspace/channel/key ID. Lazy key rotation uses compare-and-swap; expired tokens require reconnect, never assumed renewed. Private credentials have no table grants. Provider errors/payloads/secrets are not returned to browsers. Next server-action argument logging is disabled; webhook URLs are excluded from request logging.
- Voice: authenticated Meta media lookup, phone binding, allowlisted HTTPS CDN/no redirects, bounded 16 MiB body, exact byte count, metadata/event SHA-256, magic checks and decoded duration. OGG/WAV/MP3/MP4/WebM supported; AMR/raw AAC require human handling. STT max 120 seconds, Iraqi/mixed Arabic-English faithful transcription prompt, confidence/no-speech checks and human fallback. Recognition quality is NOT proven by mocks. Owner-only streamed playback/download uses fresh authorized media lookup and a workspace rate cap. No public media URLs or persisted raw files.
- Team: owner-generated expiring invitation fragment link, hashed token at rest, confirmed `auth.users` email binding, member-only role, atomic existing subscription membership guard, revoke and member removal. No outbound invitation email service is configured: owner shares link securely. Removing a member does not delete their Auth identity or business history. Invitation retry is idempotent only for the same accepted current member.
- Billing: plan-change, cancellation and renewal requests, history/withdrawal and trusted audit review. Review ends at `approved_pending_activation`; it never updates entitlements, renews a trial or activates a paid plan. Payments remain disabled. Current trial/backfill/expiry rules are unchanged; expired businesses need a separately approved recovery policy.

## Operations and decisions needed

- Alert on webhook 503 rate, unresolved queue at 500/800/1000, oldest accepted age, projection failures, expired credentials, unknown deliveries and worker throughput. Use the prepared read-only `docs/sql/cloud-runtime-monitoring.sql` after an approved installation. Poll aggregate counts only; do not log payloads/tokens/phone IDs. There is no automatic monitoring deployment in this change.
- At saturation, return 503; never delete unresolved events to acknowledge a retry. Meta retries are finite: arrange an operator response before the retry horizon. Reconcile mapping/entitlement/provider issues, restart bounded processing, verify event IDs/deduplication, and request resend only where durable acceptance cannot be established. Do not fabricate delivery or replenish quota to resolve ambiguity.
- Expired/quota-exhausted intake remains privately durable but does not become an active conversation. Restore entitlements only through separately authorized operator action; deferred jobs retry periodically. Five-attempt processing failures go to review. Use private `review_cloud_attempt` only with provider evidence; `sent_proven` does not claim delivered/read, and `not_accepted` requires explicit approval/retry. No owner browser can invoke operator functions. Record evidence IDs outside sensitive message logs.
- **Voice retention gap:** stored event/media reference is durable; Meta-hosted binary availability is finite. Long deferred audio may become unretrievable. Choose an approved encrypted object-storage/retention strategy or a short bounded backlog SLA before pilot; do not claim lossless permanent voice retention. The current system keeps transcript once successfully obtained, never raw audio on disk.
- Owner must approve customer notices/consent, transcription region/provider retention, deletion/DSAR process, transcript/message retention, audit retention, encrypted backup/key recovery, expired-trial communications, appeal/recovery and manual subscription operations. No policy was assumed approved. New private jobs/attempts are not auto-purged; implement approved retention before pilot, preserve dedupe tombstones across the retry horizon.
